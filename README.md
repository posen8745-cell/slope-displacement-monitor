# 順向坡雨量警戒模擬系統

**基隆私立二信高中｜P2C29｜張博程**

> **高中自主學習作品｜連續豪雨情境模擬｜坡地監測裝置延伸認識**
>
> 本系統為教育與展示用途，**目前僅模擬雨量與雨量警戒，尚未安裝或串接坡地位移感測器，也不具備實際崩塌預測能力**。

## 一、作品介紹

### 自主學習動機

在基隆求學的過程中，我留意到基隆多山的地形，以及國立臺灣海洋大學附近的坡地環境，因此開始關注豪雨與坡地安全的關係。我想先從較容易理解的雨量資料與警戒提示出發，練習設計一個可以操作、觀察數據變化的模擬系統。**這些生活觀察是學習動機，並不表示已確認海大周邊特定坡地屬於順向坡；是否為順向坡仍須查閱地質資料並由專業判定。**

順向坡是岩層傾斜方向大致與坡面傾斜方向一致的地形。在某些地質與工程條件下，降雨入滲、地下水壓變化及岩層弱面可能影響坡地穩定性。由於**降雨量不等於坡地位移量**，實際坡地安全評估還需要地質調查及專業監測資料。

本作品先以「雨量監測」為切入點，利用 HTML、CSS、JavaScript 與 JSON 建立可在瀏覽器操作的**順向坡雨量警戒模擬介面**。使用者可切換一般降雨或連續豪雨情境、觀察每 10 分鐘模擬雨量與累積雨量，以及查看自訂門檻觸發的燈號、聲音和事件紀錄。後續可再研究如何連接地表傾斜計、地表伸縮計、地中傾斜儀與地下水位感測器。

### 自主學習目標

1. 理解「降雨誘發因素」與「地表／地中位移」的差別。
2. 練習多站點 JSON 資料讀取、累積雨量計算與歷史紀錄管理。
3. 設計雨量變化圖表、分級警戒及視覺與聲音提醒。
4. 以連續豪雨模擬測試系統的門檻判斷與介面回饋。
5. 研究未來擴充成「感測器 → 資料收集 → 遠端監測介面」的可能性。

## 三、模擬資料來源與測站

程式優先讀取與 `index.html` 位於**同一層**的 `mock_cwa.json`。目前資料為自行設定的虛構站點，格式參考測站資訊結構，**不是中央氣象署即時 API 或真實觀測**。

| 站點編號 | 模擬站名 | 雨量基準值（每模擬 10 分鐘） |
| --- | --- | ---: |
| `C0A9F0` | Mock Station – 坡地 A | 2.5 mm |
| `C0B120` | Mock Station – 坡地 B（暴雨測試） | 10.0 mm |
| `C0C330` | Mock Station – 下游 C | 0.5 mm |

座標用於「最近站」示範計算，不表示該站真的裝設在對應的順向坡。

### 兩種降雨情境的演算方式

**一般降雨**：以各站的雨量基準值為起點，每次更新加入小幅隨機雨量，另有約 10% 機率出現較大的隨機增加量。結果並非真實天氣。

**連續豪雨**：以各站雨量基準值 `base` 加上持續增加的額外雨量 `extra`，再加入小範圍隨機波動 `jitter`，形成逐步增強的模擬。

```text
模擬第 n 次更新（從 n = 1 開始）：
extra = min(15, 2 + 0.45 × (n - 1))
10 分鐘模擬雨量 ≈ base + extra + 隨機值（0 ～ 0.7）
```

連續豪雨的預設參數設定在 JSON：

| 參數 | 預設值 | 說明 |
| --- | ---: | --- |
| `initialExtraMm` | 2.0 | 初始額外雨量（mm） |
| `growthPerStepMm` | 0.45 | 每次模擬更新增加的雨量（mm） |
| `maxExtraMm` | 15.0 | 額外雨量上限（mm） |
| `jitterMm` | 0.7 | 隨機波動上限（mm） |

範例：若測站 A 基準值是 2.5 mm，第一次連續豪雨更新得到的 10 分鐘模擬雨量約在 **4.5～5.2 mm** 之間。隨著更新次數增加，額外雨量逐步上升，到達上限後維持在該範圍附近波動。

切換模擬情境會**重置連續豪雨的增強步數，但保留已產生的歷史紀錄**。如需從零開始觀察新的累積雨量，請按「清除本機歷史」。

## 四、警戒判定原理

系統以選定測站的 **24 小時模擬累積雨量 `R24`** 判斷燈號；門檻可在畫面上自行調整，預設值如下：

| 燈號 | 預設條件 | 畫面意義 |
| --- | --- | --- |
| 🟢 綠色 | `R24 < 80 mm` | 未達示範注意門檻 |
| 🔵 黃色（畫面使用偏藍色圓點） | `80 ≤ R24 < 150 mm` | 示範注意狀態 |
| 🟠 橘色 | `150 ≤ R24 < 200 mm` | 示範警戒狀態 |
| 🔴 紅色 | `R24 ≥ 200 mm` | 示範嚴重狀態 |

> 這組 **80／150／200 mm 是自行設計的展示門檻**，不是官方順向坡崩塌預警值，也不能拿來判斷任何實際場址是否安全。畫面中的黃色等級目前採藍色提示點，屬既有介面配色。

累積計算概念：

```text
R24 = 模擬時間往前 24 小時範圍內，各筆 10 分鐘模擬雨量之和
R72 = 模擬時間往前 72 小時範圍內，各筆 10 分鐘模擬雨量之和
```

**重要限制：** 若模擬資料尚未累積滿 24 或 72 小時，顯示的是「目前已有的模擬紀錄總和」，**不是完整 24／72 小時觀測累積量**。程式對每站保留至多 432 筆紀錄（以每筆 10 分鐘的模擬間隔計算，相當於最多 72 小時）。

## 五、順向坡位移監測究竟要連接哪些裝置？（研究與未來擴充）

本自主學習作品目前只有雨量模擬，**並沒有「位移感測器」連線或位移數值**。若將來要研究真正的順向坡位移監測，可依欲量測的物理量選擇以下裝置：

| 裝置 | 安裝或觀測位置 | 主要量測內容 | 與本作品的關係 |
| --- | --- | --- | --- |
| **地表傾斜計（Tiltmeter）** | 坡面穩定固定點或構造物 | 坡面局部傾斜角度及變化 | 可作為感測原理的學習與展示，但**角度不等於位移距離** |
| **地表伸縮計／地滑計（Extensometer）** | 坡面兩測點之間，或跨越可能變形區 | 兩點間相對位移、伸長或縮短（mm） | 適合呈現「是否持續移動、位移速度是否增加」 |
| **裂縫計（Crackmeter）** | 地表、擋土結構或岩體裂縫 | 裂縫寬度的相對變化（mm） | 可顯示局部裂縫開合，不代表整座坡體的總位移 |
| **地中傾斜儀／定置型傾斜儀（Inclinometer／IPI）** | 經專業設計的地中監測孔 | 深度方向的側向變形、可能滑動區位置 | 較專業的坡體內部變形監測，需鑽孔及專業判讀 |
| **GNSS 位移監測站** | 坡面固定觀測點與穩定參考系統 | 長期三維位置變化 | 適合監測表面位移趨勢，須控制精度與環境誤差 |
| **地下水位計／孔隙水壓計** | 地下水觀測井或監測孔 | 地下水位或孔隙水壓變化 | 用於研究豪雨入滲及地下水變化，**本身不是位移計** |
| **雨量計** | 開闊、適合降雨量測的位置 | 單位時間降雨量及累積雨量 | 是本次模擬的主題；雨量是可能的誘發因素，不是坡體位移量 |

### 與坡地位移監測相關的兩種裝置

目前系統以**模擬雨量**呈現警戒變化，尚未連接位移感測器。若未來要擴充位移監測功能，可以進一步了解以下兩種裝置：

1. **傾斜計（Tiltmeter）：** 量測固定位置的傾斜角度與變化，用於觀察局部傾斜趨勢。**傾斜角度不等於坡體位移距離**；教學用傾斜感測器可以展示量測原理，但不等同於工程級監測儀器。
2. **地表伸縮計（Extensometer）：** 量測坡面兩個固定測點之間的**相對距離變化（mm）**，用來觀察地表是否持續變形，以及位移變化的速度。若實際安裝於坡地，仍需專業選點、校正及維護。

**與本作品的關係：** 以上裝置屬於未來可能擴充的監測資料來源，**不是本系統已經安裝或串接的設備**。目前完成的功能仍是雨量與警戒門檻的模擬。

真正的順向坡是否有滑動風險，還需要地質構造、岩層傾角、滑動面、降雨、地下水與歷史位移等資料共同研判；**沒有單一通用感測器或雨量數字，就能保證安全**。

## 六、操作方法

1. 使用 GitHub Pages 網址開啟系統，確認模擬站點清單正確載入。
2. 選擇站點；也可以填入案場座標後按「自動選：最近站」，或按「自動選：最大雨量」。
3. 在「降雨模擬情境」選擇 **連續豪雨（逐步增強）**。
4. 建議示範時選擇 **每 10 秒（Demo）**：每 10 秒更新畫面，**但每次都代表模擬時間前進 10 分鐘**。
5. 使用預設示範警戒門檻，點選「開始監測」。
6. 觀察雨量 KPI、各站曲線、比較表、警戒燈號、更新倒數及事件紀錄。
7. 需要重新觀察從零開始的 24 小時累積時，先按「停止」，再按「清除本機歷史」，接著重新啟動。
8. 結束後可按「停止」。如需清掉這台裝置／此瀏覽器保存的紀錄，按「清除本機歷史」。

**注意：** 網頁須開啟並執行才會在本地端定時更新，這不是雲端 24 小時背景監測服務。部分瀏覽器會在背景分頁減慢計時。若警戒聲未播放，可能與瀏覽器自動播放政策有關。

## 七、部署到 GitHub Pages

本專案不需要 Node.js、Python 伺服器或額外套件即可放到 GitHub Pages。建議儲存庫檔案結構：

```text
repository/
├── index.html       # 模擬系統主程式
├── mock_cwa.json    # 虛構測站和連續豪雨參數
└── README.md        # 專案介紹與感測器研究說明
```

1. 將三個檔案上傳到 GitHub 儲存庫的同一層目錄。
2. 到儲存庫 **Settings → Pages**，將發布來源設為部署分支（例如 `main`）與網站根目錄（`/root`），儲存設定。
3. 待 GitHub Pages 建置完成後，開啟網站網址進行測試。
4. 若頁面顯示 `DEMO01` 等內建示範站而非 `C0A9F0` 等自訂站點，請檢查 **`mock_cwa.json` 檔名與相對路徑**。

**常見錯誤：** 若把 JSON 上傳成 `mock_cwa(1).json`，但 `index.html` 使用 `fetch('./mock_cwa.json')`，就會讀取失敗並改用內建示範站。

### 學習歷程可用的作品摘要

這次自主學習以順向坡降雨監測為主題，建立一套可在瀏覽器操作的雨量警戒模擬系統。我使用 JSON 設計虛構測站資料，並以 JavaScript 模擬一般降雨與連續豪雨兩種情境，讓系統能計算 10 分鐘雨量及 24、72 小時累積雨量，再依自行設定的門檻顯示分級警戒、圖表與事件紀錄。製作過程中，我練習資料讀取、陣列與時間序列處理、介面設計及模擬測試，也進一步研究了地表傾斜計、伸縮計與地中傾斜儀等坡地監測裝置的用途。我了解到雨量只能代表可能影響坡地穩定的因素，不能直接等同於坡體位移，因此目前將作品明確定位為教育用模擬系統，未來再考慮加入感測器資料與更完整的監測分析。

## 九、限制與後續規劃

**目前限制**

- 全部雨量皆由程式模擬；JSON 中的測站名稱、座標和數據為展示用途。
- 不含現地坡度、岩層位態、滑動面、地中變形、地下水位與位移感測資料。
- 警戒燈號只依使用者可修改的 R24 雨量門檻判斷，不能當作實際的崩塌風險評估。
- 累積雨量在資料未滿完整時段前，只能表示「目前模擬歷史的累計」。
- 瀏覽器本機保存的資料不會自動同步到其他裝置，也不是長期持續監測的正式系統。

**後續可研究的方向（尚未完成）**

1. 加入**模擬傾斜角與模擬位移量**，展示位移與雨量的資料區別。
2. 以教學用傾斜感測器進行室內傾角實驗，練習讀取和顯示數值。
3. 研究伸縮計的相對位移量、位移速度與時間序列分析。
4. 研究地下水位／孔隙水壓與降雨入滲之間的關係。
5. 若未來要進行現地監測，再由專業人員選定儀器、監測位置、校正方式與警戒基準。
